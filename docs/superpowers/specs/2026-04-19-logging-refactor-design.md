# Design Spec - Logging Modernization to Loguru

**Topic:** Replace `logging` with `loguru` and convert `print()` to `logger` calls.
**Date:** 2026-04-19
**Author:** Gemini CLI

## 1. Introduction

The `pyfastspm` project currently uses a mix of the standard `logging` module and `print()` statements. In some files, a transition to `loguru` was started but is incomplete or inconsistent (e.g., `fast_movie.py`). This spec outlines the plan to fully migrate to `loguru`.

## 2. Proposed Changes

### 2.1. Library-wide logger configuration
- `pyfastspm/__init__.py` already contains `from loguru import logger` and `logger.disable("pyfastspm")`. This is correct for a library.

### 2.2. Import and Definition Updates
- **Search and Replace:** In all `.py` files within `pyfastspm/`:
    - Replace `import logging` with `from loguru import logger`.
    - Delete `log = logging.getLogger(__name__)` or `logger = logging.getLogger(__name__)`.
    - If a file already has `from loguru import logger` but also has `log = ...`, the latter should be removed.

### 2.3. Unified Logger Name
- To match the `loguru` convention and the user's request, the logger variable name should be `logger`.
- **Global Rename:** Replace all instances of `log.` with `logger.` (e.g., `log.info` becomes `logger.info`).

### 2.4. Print Statement Conversion
- All `print()` calls in the codebase will be converted to `logger` calls:
    - **Informational/Status Messages:** `logger.info()`
    - **Errors/Exceptions:** `logger.error()`
    - **Warnings (e.g., fallbacks):** `logger.warning()`
    - **Detailed Debug Info:** `logger.debug()`
- Specific attention to:
    - `pyfastspm/tools/error_catcher.py`: Convert prints to `logger.error`.
    - `pyfastspm/artefact_removal/drift.py`: Convert prints to `logger.info`.
    - `pyfastspm/artefact_removal/creep.py`: Convert prints to `logger.info` or `logger.error`.
    - `pyfastspm/artefact_removal/fft.py`: Convert prints to `logger.info` or `logger.warning`.

### 2.5. FastMovie.close Fix
- The `FastMovie.close` method in `pyfastspm/fast_movie.py` is currently trying to use attributes from the standard `logging` module on a `loguru` logger.
- **Fix:** 
    - Store the handler ID returned by `logger.add` in `self._handler_id`.
    - In `close()`, use `logger.remove(self._handler_id)`.

## 3. Architecture & Data Flow
- Standard `loguru` usage: `from loguru import logger`.
- The `FastMovie` class will continue to use `logger.bind(file_name=...)` to provide context-aware logging for data processing.

## 4. Testing
- Run existing tests using `pytest`.
- Verify that the `.log` file generated by `FastMovie` still contains the correct processing entries.
